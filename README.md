## ◈ whoami

I'm a software engineering student who likes going deeper than simply making an application work. My projects tend to move toward **real system behavior** — authentication, business logic, APIs, databases, event flows, observability, anomaly detection, and architecture.

I'm interested in the point where software stops being a collection of features and starts behaving like a **system**.

> `curiosity → understand the problem → build v1 → break it → find the real bottleneck → redesign → build it properly`

## ◈ How Projects Take Shape

```text
problem → model the system → define the data → build the core workflow
   → test the ugly cases → observe what actually happens → improve the architecture
```

The interesting part is rarely the first working version — it's what happens **after it breaks**.
